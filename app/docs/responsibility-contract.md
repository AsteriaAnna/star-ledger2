更新2026-10-05，保留R01–R14/C01–C06编号；本文定义目标责任，不表述实现完成。真实状态看 [当前状态](project-status.md)，执行顺序看 [唯一计划](m1-m7-execution-plan.md)。原完整版本保存在 [历史快照](archive/responsibility-contract.md)。

## 层次与单一规则来源

用户提供本人知道的事实和真实偏好，只回答系统缺乏证据的问题。UI收集最少输入、显示结果和保留草稿；应用服务编排解析、去重、最新快照、原子命令和任务结果；领域/账务核心负责金额、资金与消费、不变量；查询负责统一口径/下钻；存储与同步负责可靠持久化、完整批次、历史/恢复/冲突，不改变业务含义。

结构化确定事实→适用稳定记忆→候选推断→必要询问。AI可给分类/用途或识别候选，不能覆盖明确来源、用户更正或猜测到账。手机与电脑适配入口不同，不能重复实现经济事件规则。

| R13 | 选范围并查消费明细 | 单一日期入口/快捷范围、统一消费贡献；概览/分类/日期/明细一致、点击可下钻；设备偏好本地 |

## 六条必须保持的契约

- C01 字段权威：原始来源不可改写；用户修改字段不被重导/新规则静默覆盖；金额、账户、时间、性质与分类建议分开。实质变化需要字段差异与明确选择。
- C02 身份与证据：一个namespaced来源身份对应最多一笔有效经济事件，可有多份不可变证据版本；一笔交易可有多个来源，一份证据只归一笔。弱相似仅候选；截图/文件/设备重试不重复入账。
- C03 状态与问题：PENDING不产生实际资金/消费，后续成功只结算一次；FAILED不占成功身份。核心事实未知才暂缓该条，账户/关系缺失不抹已知事实；问题回答、必要账务/记忆/结果同一原子任务，可重试也可放弃输入。
- C04 修改与关系：用户提交改动意图，不用旧表单覆盖未改字段；最新快照下统一规划金额/账户/消费/关系，失败全回滚。真实歧义保留可处理问题，技术故障不能伪装成关系不明。
- C05 记忆与恢复：记忆有平台/profile/渠道范围，失效/冲突停止复用；一次选择不自动泛化。软删除普通重导不复活，恢复显式且保留更正；撤销不能误删复用旧账；换设备/密码恢复沿用原账密钥。
- C06 派生与持久化：余额/消费、来源/更正历史分开，未知余额≠0，输入实际余额先只读比较，冲突不输出假确定合计。Web IndexedDB与SQLite/原生可靠性分别验证，设备入口共用业务结果。

## 数据归属与身份边界

| 数据 | 归属/边界 |
| --- | --- |
| 个人Transaction、Movements、Effects、来源证据、关系与修改历史 | 本人账本正式操作，完整批次持久/加密同步，不能跨UID混入 |
| 月预算、分类目录、账户识别记忆/来源决定 | 账本级操作，限定记忆范围，真实云往返仍需验收 |
| ExternalRecord、Interpretation、Attention、Session/逐项Outcome | 本机导入工作区及恢复；不自动同步整个临时过程 |
| 未保存草稿、勾选与显示偏好 | 本机/会话，草稿保留方案需单独验证，勾选不跨筛选范围 |
| 原图片/原xlsx | 当前不长期存档；截图保留OCR文字/指纹/提取字段，文件保留原始行；多图/AI不自动改变此边界 |
| 云账号UID、ledgerId、资金accountId、来源profile | 四者分开；手机号/昵称/登录方式改变不新建UID或换账本 |
| 双人关系与授权 | 独立关系，不合并个人账号/密码；服务端访问与解密授权一起设计，具体可看/编辑/解绑待确认 |

旧GitHub/旧本机迁移取消，备份恢复保留；原图存档、工作区跨端接力、共同资金和旧情侣存款规则没有新授权。实现前核对本任务的用户案例、原子性、金额/关系、证据和恢复边界，完成后分别记录本地/云/浏览器/真机。
