# M5.2 改账进度

## M5.2-A：编辑请求与草稿安全

已接通名称、备注、分类的 changedFields + expectedSnapshot 应用入口。界面不再直接 PATCH 这些详情字段；服务检查最新快照、冲突、可编辑字段，持久化适配在同一 mutate 中规划与执行。未改字段不随表单整体覆盖。

草稿独立存储于本机 localStorage，以设备和编辑窗口隔离，不写账务、不进同步或账本备份。关闭弹窗、下一笔/上一笔、刷新、关闭标签页后可从页面提示恢复。保存成功后清理；主动放弃不改账；源交易已删除仍可复制草稿内容或放弃。清理网站数据会清掉草稿，此机制不代替备份。

并发修改被拒绝后，显示最新值与草稿；用户明确选择按最新账单继续编辑后只更新基准，不立即写账。未编辑字段取最新值。已删除交易不能借草稿恢复。

本机暂存失败时阻止替换/关闭编辑界面，保留输入并启用离开保护；仍允许尝试直接保存账单。账务写入失败保持编辑界面，可重试。保存期间阻止继续输入和替换弹窗。

验证：41 个底层测试文件通过；核心/Web 类型检查与构建通过。浏览器导入回归与新增编辑场景共同执行，覆盖切换/刷新/关标签、跨窗口修改、IndexedDB 事务中止、草稿配额错误、主动放弃、删除后找回草稿。运行结果为本轮本地浏览器验收，不能代替真机验收。

范围：此节点不是完整改账完成。金额、账户、日期、性质仍使用既有入口或尚不能直接编辑；完整 Correction Service 接入、字段保护、关系待办落在 M5.2-B/C。

## M5.2-B/C：统一财务字段与关系维护（2026-10-04）

主要路径已接通：详情可一次修改金额、实际账户、北京时间、交易性质、分类、名称、备注；支持单账户/组合支付转换、外部代付、转账、还款、提现手续费和外转消费分配。删除了详情页旧“更正金额＋必填理由”入口。核心仍保留旧命令兼容既有数据与历史测试。

职责实现：
- `accounting/transaction-intent.ts` 从当前有效流水（或待完成计划）还原资金结构；不依据页面标签或原始来源覆盖当前账务。
- `application/transaction-edit.ts` 接收实际变更字段和快照；财务字段由 `transaction-financial-edit.ts` 调用 Correction Service，在最新状态下规划，Web 适配器原子提交。
- Correction Service 只把明确的关系业务矛盾转为待处理关系；未知错误继续抛出并回滚，不再由宽泛 catch 吞掉。
- 有效退款自动重连；无效关联的解除记录与账务修改同事务保存。`detachedRefundReviews` 从已持久化的关系解除记录和有效退款事实推导提醒，无需另建一套待办状态机；刷新/同步后仍可推导。
- PENDING 修改只更新未来计划；新增测试覆盖修改后成功结算一次。有效流水查询排除归零的旧更正流水，避免误报自己转给自己。连续更正同毫秒的流水 ID 也能区分。

字段保护基础：新增 Transaction 可选 `user_edits`，记录用户明确改过的字段范围，与本次账务操作原子写入并同步。SQLite 顺序迁移至 schema 8，旧记录默认 null；Web 投影兼容旧操作。**M5.1-D 尚未消费这个标记实现完整重导字段保护，本轮不能宣称该需求全部完成。**旧客户端不认识新字段，混合版本同步属于 M6 兼容验收门槛，本分支未部署。

验证：42 个测试文件共 333 个测试通过，核心/Web 类型检查、构建通过；25 个浏览器场景通过（15 导入/选择范围、6 草稿保护、4 财务编辑）。涵盖来源不变、负债符号、退款重验/超额集合、组合金额、PENDING 计划、全事务回滚、schema 迁移和字段标记双设备模拟同步。浏览器为合成数据；338 条真实样本和真实双设备未重跑。移动宽度检查通过；运行环境缺中文字体，截图不能作为中文字体质量验收。
