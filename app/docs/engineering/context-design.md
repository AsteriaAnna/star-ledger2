# AI 上下文设计依据

核对日期：2026-10-13。仅在调整 AI 工作方式或追溯研究时查阅，不是每次开发必读。

## 官方说明与本仓库判断

| 可核实的机制 | 对星账的落实 |
| --- | --- |
| Codex 按全局及仓库根到工作目录发现 AGENTS/override；并非任意 MD 都自动加载；文档说明默认项目指令上限 32 KiB。[1] | 保留一份短根规则，普通资料通过明确任务入口按需读取。32 KiB 是上限，不是推荐填满的预算。不同宿主需核实实际加载机制 |
| 官方建议避免每次修改强制读整套文档，按服务边界、数据库或部署任务触发相关内容。[2] | 产品、当前工作、代码地图各有用途；历史报告退出默认读取。缩短不能删掉账务原子性和真实入口等必要边界 |
| Skills 先提供名称/描述，再按需加载正文和资源。[3] | 采用相同的按需披露原则；目前没有反复出现且需独立封装的新流程，因此不为存资料新增 Skill |

**工程判断，不是官方保证：** GitHub 文件提供可检索的外部记录，不等于模型永久记忆，也不保证自动加载。archive 目录不是搜索隔离或权限边界；常规检索应限定源码范围，只有追溯时纳入历史。旧对话已进入上下文的内容也不会因文件搬迁自动消失。

以实际读取范围、重复检索、是否误用旧结论衡量效果；不以文件行数代替 token 成本。本轮没有精确计量 token 节省，也未验证其他 AI 客户端的指令加载。确定性约束应由现有业务代码和相关检查共同保护，不能只依赖提示词。

如果用户明确要求多 AI 协作：分别给任务目标、固定 SHA、相关路径、边界与验收；避免各自获得整段历史并重复研究。主线汇总实际提交和证据，确认重叠后集成；不能将支线建议自动提升为共识。当前不因此启用多代理或另建协作体系。
