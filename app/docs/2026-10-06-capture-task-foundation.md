## 已实现规则

| 场景 | 行为 |
|---|---|
| 刷新/重开 | 持久按用户/账本列出任务，取得接受点、结果引用和版本；不依赖旧进程内存 |
| 上传不明确 | 进入RECONCILING，禁止直接重发；查询旧请求确认已接受后继续原任务，或明确安全后重试 |
| 执行租约 | 两个执行者只能一个通过版本比较领取；响应必须匹配当前attempt、lease和version |
| 模型超时 | 租约到期转RECONCILING，不能视为“服务商未处理”；核对旧请求后决定采用结果或安全重试 |
| 重试 | 整个任务自动重试最多一次；用户明确重试不重置自动次数；重新领取增加attempt |
| 待补字段 | NEEDS_INPUT→READY复用结果，不能自动重新调用AI |
| 取消 | 正式事务提交前均可取消，包括COMMITTING；旧版本不能完成，迟到响应不入账 |
| 完成 | 完成标记、账务和既有import outcomes必须同一持久事务；失败一起回滚；重复完成不执行写账回调 |
| 完成后的删除 | COMPLETED拒绝取消；使用普通交易删除/恢复能力，具体接入在K04/K06 |
| 图片清理 | 完成/取消/任务过期标PENDING；外部清理确认后才标DONE并移除imageRef，结果引用和收据保留 |

内部状态包含LOCAL_QUEUED、UPLOADING、ACCEPTED、ANALYZING、RECONCILING、READY、NEEDS_INPUT、COMMITTING、COMPLETED及失败/取消/过期。RECONCILING是原计划超时“先查旧请求”的明确表达，不新增用户日常需要操作的队列。

ACCEPTED在基础服务中只记录适配器传入的remoteTaskId/imageRef，不能证明真正云接受；READY保存版本化结果引用，实际JSON/字段/财务校验在K04完成。图片与API原文没有写入SQLite任务表。

## 原子性与未接通部分

SQLite参考适配器使用单次版本UPDATE和`BEGIN IMMEDIATE`；完成回调必须同步、只写同一数据库的账务/既有结果，不能联网/写其他数据库/调用会自行再BEGIN的现有executeBatch。异步回调被拒绝。10项测试中的写账与结果表是测试表，**尚未接入实际账务服务**。

现有LocalImportWorkspace是独立本地序列化存储，不支持与SQLite/IndexedDB账务同一事务，不能直接把它接入完成回调并宣称原子。K04需将相关outcomes与正式操作纳入相同事务，或为实际跨存储点设计可重取的持久结果协议。不得绕过这一缺口把任务先标完成。云端与本机完成也不能同库原子，K05需结果凭证/幂等取回。

scope分区是本地数据隔离测试，不是服务器身份认证。CloudBase必须由真实认证会话提供UID，不能相信前端任意scope。租约/取消校验将在真实PG适配器中重测；此SQLite测试不等于云并发通过。

任务expiresAt表示这次执行授权的终止时间，不等同“图片24小时TTL”。本轮没有指定默认时长；图片独立清理期限与任务保留期限须在K05适配，不能让图片到期自动丢弃已获得的事实。基础EXPIRED保留结果引用但不再执行该任务；如何从保留结果继续既有导入流程由K04衔接。
